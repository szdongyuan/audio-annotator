# 0.7.4 批量导入与列表交互验证

## 改动与兼容性

回收站和目录编辑通过项目生命周期登记，暂停正在进行的自动刷新，再提交捕获的原始操作。短暂 admission 竞争自动重试，真实版本冲突仍保留核对；退休的运行态不能写入新项目。

音频按最多 64 条准备结果提交，原生准备能力仍限定 256 条。每组只有一次完整目录校验、组织头原子提交和私人文档接收。重试保留原 UUID，已持久化但接收失败的组不能被当作未提交文件丢弃。导入期间暂停后台自动同步；完成、取消或暂停后恢复。进度通知合并，确认并行且仍受完整完成屏障约束。

ZIP 每批复用一个有缓冲的解析器，仍逐项检查源状态、元数据、长度、CRC 和指纹。目录并行读取仍完整验证每条记录；媒体与类别引用改为索引查找，不减弱原有验证。解码工作集按 64 项 / 256 MiB 目标限制，正在使用的 Arc 和单个超大音频允许超过目标；淘汰后保留校验状态并按需重建。

Windows 原子元数据替换仅针对系统错误 5/32/33 有限重试（约 2 秒），支持取消并保留原文件。短暂读句柄可复现用户看到的错误，但这不证明既有 NAS 错误一定来自该句柄；持续权限错误仍显式返回。

文件夹计数独立于所选目录；新增媒体后主动刷新目录。上下键聚焦并滚动左侧文件行，导入期间允许浏览，文件行上的空格进入播放快捷键。避免新增媒体重启尚未完成的全表状态请求，待关联面板不再交叉遍历两份完整列表。

项目、标注、身份、私人设置、共享目录、回收站与交换包格式均未改变。用户既有 NAS 项目只做了只读核对，实际写入测试使用独立目录。本次提交用于 PR 评审，尚未合并至 main 或发布正式 Release。
