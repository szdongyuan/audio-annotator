# Global UUID Identities Implementation Plan

> **For agentic workers:** REQUIRED: Use the `subagent-driven-development` skill to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace project password accounts with global, portable UUID identities usable before opening a project, while preserving safe per-author collaboration.

**Architecture:** A native application-local profile store supplies process-selected identity metadata. Collaboration format 3 adopts that UUID directly into credential-free author records; existing workspace, catalog, publication and admission machinery retain ownership and personal state. React provides compact application-level identity actions and project-aware guarded switching.

**Tech Stack:** React/TypeScript, Tauri 2, Rust/serde/uuid, existing atomic filesystem helpers, Vitest and native WebDriver desktop tests.

## Contract intent
Profile: `{authorId, displayName, createdAt}`. Local file: versioned kind, monotonic revision, last-selected UUID and profiles. Portable file: distinct kind/version and one profile only. Exact kind strings belong in shared constants. No password, login-name, secret or project path fields.
Profile list/create/rename/import/export/select responses must expose validated snapshots and explicit partial rename warnings. A useful shared response is `{profiles: ProfileSnapshot, transition: Transition|null, warning: AppError|null}`; native/backend may choose a narrower consistent equivalent before frontend implementation. Snapshot includes store revision, this process's selected UUID and all validated profiles, plus runtime/project expectation needed for a no-project command. Mutating expectations bind profile revision, runtime nonce and nullable project ID/revision. Native export/import receive picker-selected paths, not arbitrary author storage paths. Document the final IPC contract in Task 2 evidence.
Successful profile selection must have no fallible runtime installation remaining after persisting last-selected. Profile creation/import and selection are separate operations: creation/import may remain saved after a failed explicit use, but failed selection never changes the old active identity/workspace. Reuse existing cancellation and publication barriers, not a second editor lifecycle.
