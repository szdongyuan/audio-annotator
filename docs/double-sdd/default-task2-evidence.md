## Native handoff

- `LocalProject::adopt_shared_catalog(&mut self, id: &str, revision: u64, repo: Arc<CollaborationRepository>) -> Result<ProjectSnapshot>` is the live adoption entry point. Fetch `old_repo.reload_catalog()` outside the application mutex, then install the returned verified repository behind the native runtime/actor nonce and expected-revision barrier. Core verifies the canonical shared root, fixed manifest identity, unchanged project metadata, and exact old public descriptors by UUID membership. A different root, changed descriptor, removed old medium, or stale document revision fails without changing the live session/history. An unchanged catalog is a true no-op (no private writes/revision change). Catalog growth increments saved and live document revisions once each, preserves their existing difference and timestamps, and does not create a content undo step. Native must replace its own repository/registry context after successful adoption; the workspace replaces its repository internally while retaining the existing actor lease.
- Adoption stages a cloned session including both undo/redo stacks, extends every document in deterministic catalog UUID order, then commits the durable private envelope before installing that session. Existing paths, notes, categories, annotations, masks, analysis, mix, view, and playback preferences are retained. Added media receive only default analysis/mix/labels. No share I/O occurs in adoption: it uses the caller's already verified repository view and writes only the local recovery/main envelope. Failed local writes leave live state/history/repository unchanged; a complete newer recovery proposal still requires explicit recovery selection on restart.
- `PrivateWorkspace::open` / `LocalProject::open_shared` now reject format2 with `actor: None`. Use `PrivateWorkspace::open_view_only(repo: Arc<CollaborationRepository>, app_local: &Path)` or `LocalProject::open_shared_view_only(repo: Arc<CollaborationRepository>, local: &Path)` only after an explicit view-only request. These entry points require format2. `PrivateWorkspace::is_view_only() -> bool` exposes the identity mode. Format1 `open_shared(..., None, ...)` retains its original guest behavior.
- Format2 view-only state has its own `view-only` local cache directory, separate from author and format1 guest caches. `LocalProject::apply_change` permits only private masks/edits, analysis, playback mix, view and verified-identity relinks. Every annotation/category/file/channel-label mutation and raw import/removal is rejected. `workspace.save` also checks semantic public-payload equality, so direct native save cannot bypass the guard. Undo/redo stage and authorize the resulting document before installing it; private mask history remains usable. Cache validation rejects public content, pending/in-flight publication or a shared baseline in view-only state. Publication preparation returns no capture. `publish_guest` rejects format2 even for an author; the legacy guest merge remains format1-only.
- `PrivateWorkspace::hidden_media_ids() -> &[String]` and `set_media_hidden(&mut self, media_id: &str, hidden: bool) -> Result<()>` expose private visibility. The setter requires format2, a loaded catalog UUID and resolved recovery state; it is idempotent and persists the sorted private list atomically. Lists are bounded to 4096, UUID-validated, duplicate-free, and restricted to the effective catalog. Native should check its runtime/expected revision before invoking this setter and return the updated private context. Hidden IDs are independent of document history and annotation payloads; neither catalog membership nor export contents are filtered. Undo cannot undo public media additions or erase the hidden preference.
- `RememberedLayers::adopt_catalog(&mut self, manifest: CollaborationManifest) -> Result<()>` validates the unchanged-subset rule and extends layer-validation authority while retaining last verified layers. Pass the new verified repository's manifest after explicit adoption, then `update` with the full fresh snapshot (including the newly available authors/media). Polling alone must not invoke adoption. Task1's `snapshot_with_catalog` deferred author data/update flag remain the polling interface.

## Private durability and payload authority

Format2 envelopes bind `manifestHash` to `repo.manifest_identity()`, which hashes the immutable fixed manifest rather than the changing effective catalog. They retain a separate exact `catalog` descriptor list. This is necessary because `document.media[*].sourceRef` can be privately relinked; that private path cannot prove the original public descriptor on restart. Reopen validates each primary/recovery candidate against its stored catalog first, validates that catalog as an unchanged subset of the new repository, then extends the candidate document. Changed public source paths are rejected even when the document was privately relinked. Legacy envelopes need no new field and retain their old serialized-manifest identity and strict catalog ordering.

Confirmed, pending and admitted in-flight payloads are never normalized or rehashed merely because the catalog grew. Equality for format2 compares their validated projections against the effective catalog, where omitted labels and explicit empty labels have identical meaning. This also makes catalog sorting independent of old label-array order. Pending payload/hash/generation remain exact during adoption; there is no newly normalized pending payload requiring a generation bump. A subsequent actual save uses the existing generation increment and full current payload. Remote confirmation/loading retains the actual remote payload for format2 instead of synthesizing a new confirmed payload. Format1 keeps its existing empty-label behavior.

The admitted capture retains its original repository, author lease, payload, base and nonce. Adoption does not rotate the workspace nonce. Thus A can publish/ack after B was saved, C was edited live, and the catalog was adopted; B remains pending and C remains live. Restart selects B, and B can publish after A. Explicit recovery selection still rotates the nonce as before, so old-process captures cannot acknowledge a newly selected session.
