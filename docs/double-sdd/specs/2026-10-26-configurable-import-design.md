# Configurable folder and ZIP audio import

## Authorization and scope
The user requests importing audio directly from nine named ZIP archives on `N:/精成采集数据`, optionally excluding the second separately stored recording channel, with configurable folder/archive discovery. Earlier authorization explicitly requests autonomous completion without spec approval. This spec records the chosen design under that authorization. No source archives or existing NAS projects may be modified by development/verification.

## Observed source data
Read-only central-directory inspection found 3,294 WAV entries across 1,647 recording directories (including possible repeat exports, not unique recordings). Each record has `manifest.json`, `audio/CH*.wav`, and unrelated current/Excel/database files. Original exports use `records/<record>/audio/...`; cleaned archives use `<date>/OK|NG/<record>/audio/...` while manifest paths still contain the original `records/...` prefix. The supported record schema is `jingcheng-run-export-record/v2`. `audio.channels[].position` is the logical recording channel: position 1 can be CH1 or CH2; position 2 can be CH3 or CH4. Never equate the second recording channel with CH2, alphabetical rank, or a WAV's embedded channel count.

## Design choice
The exact read-only real-data fixtures (WAV counts) under `N:/精成采集数据` are: `运行记录导出20261021NG近距离.zip` (318), `2026-09-15_清洗后192条OK+NG.zip` (384), `2026-09-16_清洗后451条OK+NG.zip` (902), `运行记录导出20260909NG.zip` (32), `运行记录导出20260909OK.zip` (242), `运行记录导出20260915NG部分OK.zip` (384), `运行记录导出20260918OK.zip` (260), `运行记录导出20260920OK.zip` (412), `运行记录导出20261007NG带分类.zip` (360).

Use one discovery/preview/import workflow for folders and ZIP files, backed by native scanning and bounded streaming extraction, then reuse existing media decoding, publication, ownership, cancellation and collaboration. A source-specific Jingcheng preset interprets record manifests; a generic preset filters normalized relative paths. This is preferable to an external extraction script (not reusable in the UI) or a general plugin/scripting system (unneeded complexity).

## User workflow
- Compact File menu entries: import audio files remains; import folder and import ZIP archives open the same configurable dialog with the relevant source kind. ZIP picker permits multiple ZIPs (up to 32); folder picker selects one directory. Audio project ZIP import remains a separate existing command.
- Choose source(s), preset, recursion, extension selection (WAV/FLAC/MP3), include patterns, exclude patterns. Default generic settings: recursive, all supported extensions, include `**/*`, no excludes. Relative paths use `/`; glob grammar is deliberately limited to `*` (within one path component), `?` (one character), `**` (across directories, `**/` also matches zero directories). Matching is case-insensitive. User-requested shorthand `*/CH1` and `*/CH2` is supported: a leading `*/` is normalized to `**/` (any depth), and a final component without a dot also matches the basename without its supported audio extension; thus `*/CH1` matches `CH1.wav` and `a/b/CH1.flac`, but not `CH10.wav`. These shorthand semantics are identical for folders and ZIPs, include and exclude. Multiple patterns use separate lines (also accept comma/semicolon separators for convenient pasted lists), any include AND no exclude. Invalid or excessive rules are reported before scanning; no regex execution.
- Built-in `精成采集数据` preset exposes `导入第二路音频` (default checked). Uses manifest position 1, optionally 2; actual embedded WAV channels remain unchanged. Show the observed physical filenames and logical position in preview. Missing/malformed/ambiguous manifests are issues and are never guessed; generic rules remain available for these files. Additional positions are explicitly skipped/reported in this two-route preset.
- Save/load/delete named local rule presets and remember the last used rules on this computer, with validated bounded storage. Presets contain rules, not absolute source paths, credentials or shared project data. Built-ins cannot be overwritten. Custom generic rules such as `**/audio/CH1.wav` plus `**/audio/CH2.wav` also work without record manifests.
- Scan first, then preview counts, paginated candidate list and skipped/error details. Nothing is imported until `导入 N 个音频`. Rules can be changed and rescanned; an obsolete scan is released. Preview supports no individual checkbox selection in this iteration; rules define selection exactly. Preview contains full source-relative identity so identical basenames across records/archives are distinguishable.
- Import in bounded batches, with progress, cancellation and explicit failures/retry/discard consistent with current import ownership. Closing/cancelling preview publishes nothing. Cancelling during import retains already accepted files and reports partial results. Disk/source/read/decode failures must not silently succeed; preserved retryable publications and release acknowledgements must remain accessible.
- Imported audio display names include archive/folder name and source-relative path (bounded to existing descriptor limits without losing the filename); source files remain independent media records, not merged into multichannel WAVs. The two audio records can use existing comparison UI. All copied bytes are the original audio; unrelated archive contents are not imported. Audio and labels share through the existing catalog; rule presets stay local.

## Native discovery and staging
- Dedicated import-source module, types and runtime-owned scan tokens. Keep source inspection separate from project mutation, decoding and UI. A scan is bound to runtime identity and project; stale tokens cannot publish into another project. One active discovery/import workflow per current project controller; preserve existing direct import/relink exclusion.
- Candidate identity is source index plus entry identity, not a basename. ZIP duplicate normalized/case-folded entry paths are rejected/reported as ambiguous, never overwritten. UTF-8 Chinese names work. Unsupported/encrypted archives or encodings are explicit errors; nested ZIP traversal, RAR/7z and passwords are out of scope.
- Preserve existing folder-import exclusion of exact canonical paths already used as durable project media sources. Apply this before publishing an immutable preview, and count these as skipped. This is path exclusion only: do not deduplicate independently selected recordings or repeated exports by bytes, basename or run ID.
- Jingcheng lookup uses the manifest's own record directory plus `audio/<validated basename>` from each channel. Validate the raw manifest path as a safe relative path and the expected trailing `audio/<basename>`; do not follow arbitrary paths/pointers. This resolves cleaned relocated records without looking outside their record directory. Reject duplicate logical positions, duplicate physical assignments or conflicting manifests. Do not import OK/NG/fault_type as human labels automatically.
- Scan directory entries without following symlinks/junctions/reparse points. Bound traversal and metadata reads; report access errors. Native checks independently validate source configuration rather than trusting UI strings.
- ZIP inspection never extracts arbitrary paths. Reject absolute, drive/UNC, traversal, NUL, backslash ambiguity, symlink and Windows-invalid entries. Extract only selected audio to a unique owned local staging directory using generated safe names, streaming chunks with cancellation and CRC/length validation. Do not concatenate untrusted entry paths into extraction destinations. Keep original relative path separately for display. Source-change detection between preview and extraction must fail with rescan required.
- Hard bounds: 32 source archives, 100,000 entries total, 10,000 candidates, 256 items/page, 256 retained issue details plus total issue count, 1 MiB per manifest, 256 rules with 512 characters each, 1 GiB per uncompressed audio and 20 GiB selected audio total. Enforce both declared and actual streamed bytes; fail excessive input explicitly rather than reporting a truncated successful preview. Bounds must allow all nine supplied ZIPs. No whole archive/audio materialization in memory.
- Prefer lazy extraction per import batch to avoid expanding the complete source before preview. Staging lifetime must outlive pending decoding/publication/retry/acknowledgement, then release only owned files. Cancellation, close, error and stale-runtime handling must not remove files still used by accepted work. No archive-backed source path is stored in final media: copied audio remains playable when original ZIP is moved/deleted. Original-source changes during copy are checked.

## Compatibility / Migration
- Backward compatibility: partial.
- Protected surfaces: existing project format 2, catalog author ownership, immutable media copies, legacy explicit project reads, direct audio import/relink, exchange ZIP/JSON semantics, previous release artifacts.
- Allowed breakage: internal discovery IPC/controller contracts may change with matching frontend/backend changes and tests; existing folder import can gain a preview step.
- Migration strategy: none. New rules are local optional preferences; no project/database migration or schema expansion required just for source configuration.
