# NAS 共享标注设计（0.3.0）

## 1. 授权、目标与决策

用户要求同一 NAS 项目目录多人协作，只共享标注，各人只能修改自己的内容，重复标注必须并存；音量、屏蔽等个人操作不共享，不部署服务器。用户明确要求独立自动完成、无需批准规格。本规格的产品取舍由代理在该授权内决定，不设额外审批关卡。

推荐并采用：独立协作项目清单 + 按作者分开的共享标注快照 + 本机个人工作区。普通本地项目继续现有模式。拒绝多人覆盖一个 project.json（全文件锁和全快照历史会丢失别人的写入）；不引入服务器、共享 SQLite 数据库、CRDT 全量框架或自动合并冲突文本。

现有项目会持有 `.project.lock`，模型把媒体标签、区域标注、屏蔽、分析和视图放在同一文档，直接取消锁不安全。协作使用独立 `collaboration.json` 入口，保留现有 v2 本地文档作为个人运行投影，不修改其他用户的完整文档。

## 2. 用户流程

1. 用户先在普通本地项目导入音频，使用“文件 → 创建协作副本…”选择空目录（支持映射盘或 UNC NAS 路径），填写该项目的账号名、显示名称和密码。复制经验证的原音频，创建共享清单和创建者标注图层，然后切换到协作副本。源项目与原音频不变。
2. 同事打开该目录的 `collaboration.json`，默认访客。无需登录即可看所有人的共享框、类别、文件/通道分类和备注，并使用自己的播放、屏蔽和视图。访客创建的标注仅在本机保存。
3. “协作”菜单提供注册、登录、退出、刷新、作者显示筛选、同步状态和冲突处理。账号属于当前共享项目，不是在线账号。注册后登录自己的图层；正确密码才能进入该作者编辑会话。
4. 登录后编辑、自动保存、Ctrl+S 只改变自己的共享标注。跨作者的相同区域/相同类别/相同备注也保留独立记录，不能按几何或文本去重。
5. 登录或退出前用现有生命周期屏障提交草稿并保存在本机；个人工作区按项目路径和作者隔离。访客标注不自动归属其他账号，提供明确“发布本机访客标注到我的图层”动作：只复制标注/类别/三层标签备注，不复制屏蔽；发生自己已有文件/通道值冲突时拒绝自动覆盖，保留访客工作区并告知先另存/整理。区域复制产生新 ID，一次操作可撤销。
6. 未登录不阻止正常本地软件使用。无账号服务器、无云数据发送、无在线成员/光标聊天功能。

## 3. 数据边界与归属

共享内容是每个作者自己的类别定义、区域（时间秒/频率 Hz/通道）、区域类别与备注、文件类别/备注、通道类别/备注、创建/更新时间以及作者身份。类别 ID 只在对应作者图层中解析；同名类别可并存，类别管理只编辑当前作者。文件/通道标签同样逐作者展示，不能用一个共享 scalar 字段覆盖另一作者。

共享清单只含固定项目身份、名称、创建时间和不可变媒体目录/指纹/元数据。音频复制到共享目录下安全的相对路径，所有客户端可读。共享媒体目录本轮固定；协作状态下禁止导入、移除媒体和修改清单；要增减媒体先另存本地副本整理后创建新的协作副本。重新关联源路径仅是本机映射，不修改公共媒体身份。

不共享：音量、设备、solo/mute、播放状态、选区/定位点、屏蔽及撤销历史、STFT/Mel 分析参数、调色/增益/缩放/布局/通道可见性、缓存、个人恢复文件和本机绝对源路径。播放进度、临时选区与撤销栈仅在运行时，其他需持久化的个人设置保存在应用本机数据目录；音量/设备在身份切换时恢复该本机身份值或默认值，不能沿用另一身份的状态。原始共享媒体字节不修改。

活动 ProjectDocument 只投影当前作者的标注和其个人设置，保持现有 SelectionState/ProjectSession/undo 对自己的文档操作。其他作者图层通过独立的只读 CollaborationSnapshot 提供，绝不合并进可编辑 document.annotations、categories 或整文档历史。原生端是权限权威，不能仅靠隐藏按钮。前端传入 authorId 不能授予写入能力。

## 4. 文件格式与账号

协作清单独立严格格式 1（带明确 kind，例如 `audio-annotator-collaboration`），不是把 v2 project.json 放到公共目录。账号与图层也严格版本校验、deny unknown fields。本机缓存使用独立严格 envelope，包含个人文档、共享基线和待发布状态，不能伪装普通共享项目。

建议结构：

```
collaboration.json
media/<safe-media-id>.<ext>
accounts/<sha256(normalized-login)>.json
annotations/<author-uuid>/.writer.lock
annotations/<author-uuid>/<20-digit-revision>.json
```

账号包含不可变 author UUID、规范账号名、显示名称、创建时间和盐化 Argon2id 密码校验值。账号名 trim + Rust lowercase 后判重，允许中文，拒绝空白名、控制字符，长度 1–64 字符且 <=256 UTF-8 bytes；文件名始终由摘要生成。显示名 1–64 字符。密码 8–128 字符且 <=512 bytes，不 trim。使用固定已验证 Argon2id v19 参数（m=19456 KiB、t=2、p=1、32-byte output、16-byte 随机盐）；解析外部 PHC 时先验证参数/算法/盐/长度符合合同，不能让文件控制无限内存/CPU。注册不覆盖同名账号；无明文密码持久化、日志或前端返回；无需记住密码或密码重置功能。登录凭据只在本次 native 会话有效。

这是可信共享目录内的应用级作者隔离，NAS 文件 ACL 决定目录实际权限；不能声称密码阻止有 NAS 写权限的人直接修改文件。此边界写入指南和账号对话框的精简可展开说明，不新增常驻警示条。

新增依赖仅允许锁定 `argon2 = 0.5.3` 及其必要传递依赖，复用现有 UUID 随机源生成盐；更新许可清单，不升级其他依赖。参考：[RustCrypto 官方文档](https://docs.rs/argon2/0.5.3/argon2/)。

## 5. 并发、提交与读安全

不同作者写不同目录，互不争用全项目写锁。每个作者的可写登录会话持有 OS 文件锁，第二台机器或窗口同时用相同账号登录编辑时明确拒绝，可继续以访客查看。不得按 PID、超时或“旧锁文件”擅自删除/抢占锁；进程退出由 OS 释放句柄。

每次共享提交是整个作者标注层的不可变新 revision 文件，包含项目/作者身份、单调序号、前一版本摘要、完整标注 payload 和内容 SHA256。仅本作者目录可写。写临时文件→flush/sync→同目录无覆盖发布为 revision 文件；Windows 使用不带 REPLACE_EXISTING 的原生发布，禁止 delete-before-rename 或覆盖已存在 revision。非 Windows 测试实现需保持同样 no-clobber 合同，不将普通覆盖 rename 当作 CAS。参考：[Microsoft MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)。

发布前验证当前最新序号/摘要与本机基线一致，发布后核验当前权威仍是本次结果。竞争同一下一序号只允许一个写入成功，另一个返回冲突；失锁/旧会话不能覆盖其他人的文件或静默覆盖同账号较新内容。失败和取消仅清理本次创建的临时文件。发布成功但确认丢失时，重试发现相同作者/目标序号/摘要必须幂等确认，不重复标注。

读者忽略临时文件，只读完整合法的已发布快照。最高序号损坏、缺失、身份或摘要错误时保留最后已验证的可见图层并显示该作者错误，不能把损坏解释成删除或空层。新访客无缓存时该作者不可用，其他作者仍可见。删除是作者新快照中移除自己的记录，不删除其他作者快照。

只在成功确认后清理本作者历史，保留最新 16 个已发布版本；不清理别人的目录和未知临时文件。发现超出枚举/文件预算时明确报错，不能截断列表伪装完整。限制：账号 <=128、每层 <=16 MiB、全体已加载层 <=64 MiB；沿用现有模型的区域/类别/媒体数量和有限数值约束，并增加文件数量/序号安全整数校验。所有路径从验证过的 UUID/数字派生，拒绝越界路径、reparse/symlink 跳转和越界媒体引用。创建目标只允许空目录，最终清单最后发布；失败只清理本次拥有的 staging。

## 6. 本机保存、同步与断线

每个客户端在 app-local-data 下使用 `collaboration/<hash-of-canonical-shared-root>/<project-id>/<author-id-or-guest>/`。不得把个人缓存、恢复文件或锁写进 NAS；共享协议需要的账号注册短锁、作者写锁和共享发布临时文件除外；账号注册锁不参与作者标注的发布。缓存 envelope 原子包含个人 document、共享基线 revision/hash、最后已确认作者 payload、待发布 payload，具备损坏/中断恢复。恢复不能自动将旧本机数据覆盖较新共享版本。

保存先完整持久化本机 envelope，再异步发布标注差异。音量/屏蔽/视图等单独变更不产生共享 revision。共享失败不否认本机保存成功：显示“已存本机 · 待同步”或具体冲突/错误；不要沿用一个“已保存”让用户误以为 NAS 已更新。网络可达后重试自己的 pending，只有基线未变化才发布。

同一会话发布 payload A 期间允许继续编辑并本机保存 B。每次保存有单调本机内容 generation，发布请求捕获 A 的 generation/payload 摘要和共享基线；A 完成时在同一私有 envelope 原子推进已确认基线到 A，只有当前 pending 的 generation/摘要仍为 A 才清空 pending。若已变成 B，则保留当前个人 document、B 和其 generation，仅把 B 的下一次共享基线推进为 A；不能用 A 的旧快照覆盖 B。即使 B 的共享 payload 与 A 相同而个人屏蔽/设置不同，也必须保留最新个人 document。重启使用这个原子检查点继续发布 B，确认丢失按 §5 幂等核对。增加可控延迟发布测试，覆盖 A 在途→B 保存→A 确认→重启→B 发布及个人参数同时变化。

默认 2 秒轮询，可手动刷新；同一协作运行时最多一个网络作业，作业慢时跳过重叠请求，不堆积线程。NAS I/O、Argon2、媒体复制不持有全局项目/播放/分析锁，不堵塞 UI 和本机编辑。操作开始捕获运行时 nonce/project/actor，完成时重查；切换/退出后的旧响应不能替换新运行时、恢复旧选区或覆盖新草稿。无法取消的 OS I/O 可在后台结束，但不允许无限排队；已进入发布临界段的本作者提交可结束，UI 不接收过期结果。

其他人更新只改变独立远端图层状态，不重建当前 document、清空草稿、打断播放、重算屏蔽或污染个人撤销。本机有 pending 且共享同账号基线变更时显示冲突，暂停该作者自动发布，仍保留本机内容。提供“另存我的本机副本…”保存恢复用文档，以及“加载共享版本”明确确认后丢弃本作者 pending 并重建个人内容/历史；不提供静默最后写入获胜。退出保留已经本机持久化的待同步修改，下次正确登录同一账号再恢复；未保存内存的显式放弃沿用现有生命周期语义。

同步按钮触发先保存/提交草稿，再刷新/发布；状态区显示最后成功更新时间和错误详情，正常时只占菜单/紧凑状态按钮，不加整行教学提示。NAS 不可用时可以继续当前打开的本机工作区；不承诺无共享清单时首次打开未知项目或没有音频缓存时离线播放。

## 7. 查看与编辑界面

“协作”菜单及紧凑身份按钮显示访客/当前显示名、待同步数/错误点。账号表单是按需浮窗，外部点击/Escape 关闭纯查看/未提交表单；有正在提交的凭据、创建任务、冲突确认使用现有确认/取消边界。密码输入不复用普通笔记草稿缓存。

作者选择可“全部/仅我的/勾选作者”，默认全部。列表和只读详情显示作者、分类、备注、时间频率/通道；文件和通道的多作者分类/备注在同一按作者列表可查看。筛选仅影响显示，不能删除或保存过滤后的远端内容。当前作者自己的列表/类别管理继续原有行为。

他人框使用透明内部、边框和紧凑作者标签。点击或右键他人框可查看只读详情、播放该区域/定位；没有移动手柄、分类修改、备注编辑或删除。自己的活动选区优先保持抓取，重叠框通过作者/列表明确定位；不能因透明远端覆盖层阻止重新框选。原生拒绝对其他作者对象的伪造 update/delete；私人临时选区和屏蔽仍可作用于相同区域，但不会编辑对方对象。

自己框上的右键/悬浮条/快捷键和音频工作区继续 v0.2.1 语义。切换作者显示不切换可编辑身份；只有登录/退出流程能切换身份。切换身份清理旧选区和播放意图、等待生命周期屏障，不能把上一人的笔记或屏蔽带给下一人。

## 8. 分享、另存和兼容

普通本地 v2 项目及原完整 ZIP/JSON 功能不变。协作模式的现有导出明确命名为“导出我的标注/我的项目包”，只导出当前作者的标注/类别/三层备注与音频（完整包时）；导出 DTO 重新构造，屏蔽清空，分析/混音/视图重置为默认，剔除账号密码、他人图层、本机路径/缓存。访客导出其本机标注，清楚标识范围。不能把“完整项目包”描述成全员协作备份。全员实时协作使用 NAS 原目录，不实现协作目录压缩导入/迁移。

“另存我的本机副本…”在协作模式下产生普通本地 v2 项目，只含自己的标注和个人操作（明确是个人恢复/继续工作，不是共享导出），切换离开协作；共享目录不变。他人的数据不会被扁平化认领。新协作副本从普通本地项目建立，重复运行不覆盖已存在目标。

Compatibility / Migration:
- Backward compatibility: partial。
- Protected surfaces: 现有普通本地 v2 文档、ZIP/JSON、音频/DSP/选区交互继续可用；没有迁移要求。
- Allowed breakage: 新协作 envelope 只被 0.3.0 识别，旧程序应拒绝；协作媒体目录固定、账号项目内有效。
- Migration strategy: none。创建协作副本是显式新项目操作，不是隐式迁移旧项目或旧测试数据。v1/未知普通格式仍拒绝。

## 9. 实现边界

core 新增 collaboration 子模块，分模型/校验、账号、原子发布/作者锁、共享仓库、个人缓存与会话。LocalProject 用明确 storage/backend 分支承载普通 FileStore 和协作私有 workspace，ProjectSession 继续仅管理个人投影；所有 apply/undo/redo 经 LocalProject 权威检查，公共媒体变更在 native 拒绝。现有 FileStore 故障测试接口保留，避免笼统重写存储。

native 新增 collaboration commands/runtime（创建、状态/刷新、注册/登录/退出、访客发布、冲突恢复），使用 app local data 路径与运行时身份校验；长任务用独立阻塞作业和有界状态，媒体复制有进度/取消且复用媒体指纹合同。前端 bridge 严格解析独立协议，useCollaboration 管理状态/轮询/身份界面，RemoteAnnotations 独立只读显示，复用现有坐标和播放 API；不把远端图层塞进 SelectionState 的可写对象表。

## 10. 验收与交付

核心真实文件系统与多进程：不同作者并发同一区域均保存；自己更新/删除/撤销不改变另一作者；同账号第二writer拒绝；锁释放后可登录；旧基线/确认丢失/部分写/最高快照损坏/只读目录/断线/恢复/恶意路径/超限均不丢数据；本机设置或屏蔽变化不改变 NAS 内容哈希；注册判重、错密码、超限 PHC、伪造作者写入被拒绝。

前端：登录前后状态、隐藏作者/只读框/文件通道备注、重叠自己的框仍可编辑、外部关闭、按需布局、草稿/选区/播放不被远端刷新重置、过期响应不改新身份、冲突显式恢复、访客发布和个人导出边界。
