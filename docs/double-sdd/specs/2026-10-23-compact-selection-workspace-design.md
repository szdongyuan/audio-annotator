# 紧凑频谱工作区与统一选区：迭代设计规格

日期：2026-10-23

状态：依据用户十项反馈、整段音频与单通道均可分类的明确选择，以及菜单化/紧凑布局由开发者斟酌的授权整理；独立规格审查 PASS（2026-10-23）；用户以“ok”确认书面规格（2026-10-23），进入实施规划。尚未开始实现。

基础：当前 main `57ae4240f851167458c74239fd903b7ea1bb5ff9`；继承首版规格中未被本规格明确替换的音频、存储、交换与资源安全契约。

## 1. 目标、范围和方案

频谱是主要工作内容。消除必须先选择工具才能框选的操作，增加上下文操作和整段分类，让多通道、双文件对比拥有足够绘制面积。用户明确要求删除常驻工具教学、“已校验/原文件只读”等重复说明，并允许采用类似桌面编辑器的功能菜单。

已讨论的方案：

1. 只增加右键菜单：改动较小，但保留工具模式切换和原有空间问题。
2. 统一临时选区、紧凑菜单布局、补齐分类与文件夹导入：本轮采用，直接覆盖反馈且保留现有核心。
3. 全面重做编辑器：范围大，超出本轮需要。

交付目标版本为 0.2.0，仍是 Windows x64、React + Tauri + Rust 的本地应用。一个实施计划分为布局与菜单、选区与轴、分类与兼容、文件夹导入、集成验证几个有边界的阶段。不新增云协作、音频剪接、处理后音频导出、插件系统或 Audition 不在当前产品范围内的功能。

## 2. 紧凑布局和功能菜单

### 2.1 常驻空间预算

- 保留系统窗口框架；应用顶部采用紧凑菜单/项目状态区域和一行精简快捷操作，总高度不超过 76 CSS px。
- 底部基本播放条高度不超过 52 CSS px：播放/暂停、停止、时间/定位、循环、音量及试听模式。设备、混音表单和输出计数不再单占常驻行。
- 移除独立“分析工作区 / SPECTRAL WORKSPACE”标题行、屏蔽教学条、底部工作区状态条、常驻鼠标教学和属性区教学脚注。媒体/通道数属于文件信息，失败原因属于可处理状态，不能再占一条重复信息栏。
- 每个文件只使用紧凑标题/控制区，桌面验收尺寸下总高度不超过 56 CSS px。单声道不显示无意义的通道切换组；多通道保留紧凑通道入口。
- 参数、设备、混音、类别管理、快捷键帮助通过菜单打开 popover/dialog 或属性区，不长期占用频谱高度。无待处理错误时没有空错误栏。
- 左侧文件列表、右侧属性面板保持可折叠；右侧只显示当前对象所需编辑内容，空选择时不展示大段教学。正常状态只保留紧凑项目名称与保存状态；保存失败、数据缺失、恢复选择等可操作反馈继续明确可达。

### 2.2 菜单结构

| 菜单 | 实际功能 |
|---|---|
| 文件 | 新建、打开、保存、另存、导入音频、导入文件夹、导入分享文件、分享项目、关闭项目 |
| 编辑 | 撤销、重做、清除当前选区；所选已保存对象的删除入口 |
| 视图 | 单文件/双文件、左右/上下对比、时间轴联动、侧栏显隐、放大到选区、缩小/重置、频谱类型、分析/显示设置 |
| 标注 | 当前区域分类/备注、当前文件分类、当前通道分类、类别管理、标注列表 |
| 音频 | 原音/处理后、播放选区、屏蔽选区、整体旁路、输出设备、通道混音 |
| 帮助 | 快捷键、使用说明、版本与第三方声明 |

菜单项只绑定真实行为，按当前项目、媒体和选区启用。未完成导入、关闭/另存屏障等 editingDisabled 状态不能被菜单绕过。上下文菜单和顶部菜单调用相同的动作层，不能各自实现一套保存/撤销逻辑。

顶部主菜单与右键菜单支持鼠标、方向键、Enter、Escape、焦点返回和点击外部关闭；子菜单限制在窗口内，窗口边缘自动翻转。图层内右键不显示 WebView 默认菜单。菜单打开时不继续向画布派发拖动、播放或全局 Delete；文本编辑保留自身快捷键。

### 2.3 双文件和多通道

- 双文件默认左右排列，可通过“视图”切为上下排列；分隔线可拖动，比例限制在 25%–75%。布局与比例随项目视图保存。
- 同文件各通道继续共享时间/频率视口；两文件保持独立分析设置、可选秒级时间联动，短文件尾部留空。
- 每个通道的纯频谱绘制区最低 180 CSS px；空间充足时扩展填满。多通道超过空间时在文件面板内滚动，标题/通道入口与播放栏保持可达，不能靠继续缩小绘制区适配。
- 左右对比的每个文件面板最低宽度 300 CSS px；侧栏显隐后仍不足时，工作区横向滚动，不让控件溢出到其他面板。上下模式在每个文件无法容纳标题加至少一个完整通道时，文件栈按最小高度纵向滚动，而不是把下方文件挤成标题。
- 1280×800 外窗、100% 缩放下，默认左右对比两个立体声文件时，首屏同时显示四张完整频谱，每张绘制高度至少 180 CSS px；1920×1080 也检查。1000×680、Windows 125% 缩放及两文件各六通道允许滚动，但仍满足最低绘制高度、操作可达和没有重叠。

## 3. 统一临时选区与对象操作

### 3.1 选区状态

删除“选择/标注/屏蔽”模式按钮以及 V/A/M 模式切换。频谱始终可框选：

- 左键在空白或已有框内部拖动：创建/替换一个临时矩形选区。只有拖动超过 4 CSS px 且物理范围有效时成立；单击不制造零面积对象。
- 单击已有框选择该对象；拖边框移动，拖控制点 resize。边框与控制点命中优先于新建选区；框内仍能开始另一个选区。
- 中键拖动或 Alt+左键拖动平移；普通左键不再兼任平移。Alt+拖动优先于框选/对象移动。
- 任一时刻只有一个当前选区，包含 mediaId、channelIndex、真实秒/Hz 边界及可选已保存对象 ID/种类。临时选区不写入项目、不创建撤销项、不因关闭而产生“未保存标注”。
- Escape 取消正在进行的拖动（恢复拖动前状态），或在没有拖动时清除当前选区。菜单先消费 Escape 并关闭；输入框保留文本语义。
- 切换活动文件、项目、删除对应媒体/通道或相关对象失效时清除不适用选区。切换轴/频谱模式只重绘有效选区，不改变其物理范围。保存后的区域与屏蔽沿用原有边界校验。

区域、屏蔽、临时选区一律透明填充；类别颜色只用于边框、小型标签和列表。选中状态由线宽/虚实和控制点表示，不叠加变色面。标签限制为单行，低矮框不强行覆盖整块内容；完整名称可在悬停/属性区查看。

### 3.2 右键与快捷操作

右键已保存框：以命中的对象为目标；右键当前临时选区：以该选区为目标。空白处保留当前有效选区并提供视图/当前通道操作，不隐式创建标注。重叠对象优先命中当前选中的对象，其次按绘制层级选中最上层，并在菜单提供命中对象列表以便选择被遮挡的对象。

| 动作 | 语义 |
|---|---|
| 标注类型 ▸ | 列出项目类别和“未分类”；临时选区创建一个标注，已有标注更新类别；已有屏蔽可按相同范围另建独立标注 |
| 备注 | 选中已有标注并聚焦备注；临时选区/屏蔽先创建相同范围的未分类标注，再进入备注编辑 |
| 屏蔽选区 / Delete | 对当前范围建立可撤销非破坏性屏蔽；完全相同范围已有屏蔽时复用并启用，不重复新增 |
| 播放选区 ▸ | 原始选区/处理后选区，使用当前通道和范围；临时选区无需先保存为标注 |
| 放大到选区 | 时间与频率同时适配该物理范围；只改变视口，遵守联动时间和 Nyquist 边界 |
| 删除标注 / 删除屏蔽 | 只删除菜单目标对象，支持撤销；不会删除源音频 |
| 启用/禁用屏蔽 | 仅在命中屏蔽时显示，沿用处理版本及重新预缓冲流程 |

Delete 统一表示屏蔽当前有效选区（包括已选标注的范围），不再删除标注。已有屏蔽被选中时复用/启用该屏蔽。对象删除使用明确的菜单动作。没有有效选区时 Delete 不执行音频操作；文本、菜单、对话框内不触发此快捷键。Ctrl+Z/Ctrl+Y/Ctrl+Shift+Z、Ctrl+S 和空格播放保留。

创建标注成功后当前选择绑定新 ID，再选类别或备注更新同一个对象；创建屏蔽后绑定其 ID。标注和屏蔽仍是独立对象，按相同范围生成不建立隐含的双向同步关系。右键目标必须捕获稳定 ID/项目运行态，动作执行前重新核验，防止异步操作落到之后选中的其他媒体。

## 4. 刻度、局部放大与 Ctrl+滚轮

- 保留普通滚轮以鼠标时间位置为锚点缩放时间，Shift+滚轮以鼠标频率位置为锚点缩放频率。
- STFT 中 Ctrl+滚轮优先于 Shift：向下减小 frequencyMix（更线性），向上增大（更对数），限制在 [0,1]。按 deltaMode 归一化，支持触摸板细粒度变化。阻止 WebView 页面缩放，仅处理指针所在频谱；同文件通道同步。
- 轴混合只改变坐标，不改秒/Hz、分析参数或已保存标签，不重新计算同一视口已有 FFT。梅尔轴继续使用固定梅尔映射；Ctrl+滚轮在梅尔模式不修改视图、不触发页面缩放，相关混合菜单禁用并提供悬停解释。
- 时间刻度与频率刻度支持沿轴拖出范围后局部放大，至少 6 CSS px 才生效；刻度右键提供在鼠标锚点放大、缩小、重置该轴。放大后范围始终合法，拖动超出刻度边界时裁剪。菜单另提供完全线性/完全对数入口。
- 刻度从固定 6/5 个标签改为依视口、尺寸和变换计算的主/次刻度。采用易读数值（如 1/2/5×10^n），时间标签保持约 60 CSS px 最小间距，频率标签约 22 CSS px，次刻度至少 4 CSS px；屏幕边界上的标签不被裁掉。非线性轴依映射后的像素位置去重，不假装频率等距。
- 不增加常驻快捷键说明条。用户可从菜单、悬停和帮助发现这些操作。

## 5. 文件、通道与区域分类

用户已明确：整段音频和单个通道均能独立分类。沿用项目内统一 Category；本轮每个对象可为空或有一个类别，与既有区域语义一致。

- MediaDescriptor 新增 categoryId（nullable）和 channelCategoryIds（长度严格等于 channelCount 的 nullable ID 数组）。文件/通道备注与分类独立。
- 文件标题提供紧凑类别入口；通道标题提供通道类别入口；两者均支持右键和顶部“标注”菜单。属性区显示明确对象名称，分类结果在文件列表/对应标题可见，不依赖拖出全图矩形。
- 三层类别互不自动继承或覆盖。例如设置文件为“异常”不会改变每个通道和区域的类别。
- 事务命令明确以 mediaId 和可选 channelIndex 为目标，支持原子校验、撤销/重做、自动保存和重开。导入媒体默认未分类，重新关联必须保留原分类与备注。
- 删除类别前统计文件、通道、区域三层引用数量。确认后一次事务清空这些引用，保留媒体、区域和备注；一次撤销恢复类别及引用。
- JSON/ZIP 导出导入完整保留三层分类；类别筛选能找到整段/通道分类，结果区分对象范围，不用伪造矩形表示整体标签。

## 6. 文件夹批量导入

“文件 → 导入文件夹”选择目录，提供“包含子文件夹”选项，默认不勾选。扫描 WAV/FLAC/MP3，扩展名大小写不敏感；扫描完成后自动进入导入，进度可取消，结果显示成功、失败、已存在、跳过的数量及可展开条目。

- 扫描在 Rust 后台任务执行，拥有独立取消信号和项目运行态标识；扫描和导入期间不阻塞窗口。项目切换/关闭使旧任务失效，迟到结果不能注入新项目。
- 所选根目录先解析为确定路径；不跟随根目录内 reparse point（含目录 junction、符号链接）以避免循环和越界。不能访问的子目录/文件记录错误并继续，其余不支持扩展名跳过。
- 已导入的同一规范绝对路径跳过并报告；同名不同目录仍导入，内容相同但不同路径不自动合并。已有源被修改仍沿用现有缺失/改变/重新关联流程，扫描不能静默替换它。
- 顺序按相对路径稳定排序。扫描最多接收 10000 个候选音频、检查 100000 个文件系统条目，超限明确结束并要求缩小目录；超限发生在扫描阶段时不导入半份候选列表。
- 现有 native import_media 每批最多 256 个路径，使用有界批次串行提交，前批 native 完成且已接受文档命令处理完后再开始下一批；不能因超过 256 静默漏掉文件。前端状态与结果列表按需分页/滚动，不为所有项创建复杂 DOM。
- 单个解码/磁盘空间错误不冒充成功，其他有效文件可继续；取消保留已成功加入的媒体，停止后续扫描/解码/批次，释放未发布 PCM。保留已有失败命令 ledger 与可重试操作，不能批量“清空错误”丢失待恢复对象。

## 7. Compatibility / Migration

- Backward compatibility: partial。
- Protected surfaces: v1 本地项目、校验过的恢复/备份、JSON/ZIP 分享文件能够读取；原始音频字节、已有区域秒/Hz、类别/备注/屏蔽/分析/混音数据及项目身份保持；现有保存、锁与故障恢复保证保持。
- Allowed breakage: 用户明确要求的工具模式取消、Delete 改为屏蔽、紧凑布局和双文件默认左右排列；v2 文件不要求旧版 0.1.0 能读取。
- Migration strategy: 版本化读取兼容层与首次写入前备份。本地 ProjectDocument 和 portable Manifest 升到 formatVersion 2；分析/DSP 算法版本保持不变。

v1 先按原结构严格解析、验证校验和与语义，再迁移到 v2 内存模型。新分类默认 null/全 null，新增 compareLayout 默认左右、compareSplit 默认 0.5。保留旧的媒体/通道选择与视口范围、linkedTime 等数据。v2 字段必须完整，未知字段和未来版本仍明确拒绝，不能用宽松反序列化吞掉拼写错误。

仅打开 v1 不立即覆写原文件。首次写 v2（包括自动保存/恢复写入前）先在项目 backups 中保留原 v1 正式文件及实际采用的有效 v1 恢复候选的原始字节，采用不会覆盖既有文件的、由内容哈希区分的 pre-v2 备份名。这类迁移备份不参加普通备份轮换删除；备份失败则不发布 v2，保留内存内容并允许重试/另存。已有源项目迁移仅改变文档，不复制或写回外部音频。

v1 分享文件只在导入的新项目中迁移，原分享文件不变；新导出统一 v2，保留现有路径脱敏、流式指纹、ZIP 边界与 owned staging 契约。更新版本说明需说明旧程序不能读取升级后的项目，并提供迁移备份位置。保存提示不变成长驻教学条。

## 8. 实现边界与既有保证

- 前端分开管理临时 SelectionState、已保存对象选择和 PointerGesture；共享 ContextActions 处理顶部/右键/快捷键操作，菜单组件不直接修改持久模型。
- 持久编辑必须经过 lifecycle.enqueueEdit、草稿排空和 CommandQueue；不能复活私有异步尾队列越过关闭/另存屏障。新分类和导入结果也遵守失败归属及 revision 规则。
- 视图更新仍由 useWorkspace 登记草稿，布局/轴/比例不进入内容撤销；临时选区为内存 UI 状态。播放使用选区的物理范围，不依赖存在 Annotation ID。
- 同文件/通道切换必须释放分析 lease、pins、菜单目标及未完成手势；维持已验证的非复用 lease 与迟到消息隔离。
- 本轮不改变 DSP 滤波、CPAL callback、EOF 排空、STFT/梅尔数值定义及源身份核验。保留 PCM 96+32 MiB、native tiles 128 MiB、磁盘 tiles 2 GiB、前端数值/图像 96 MiB 总预算及队列上限。
- 原错误、取消、未保存、恢复与未知格式提示仍可达。只删除没有当前操作价值的常驻说明，不能让失败静默。

## 9. 验收与交付

1. 真实 Windows WebView2 pointer/keyboard：无需工具切换即可框选、右键分类/备注、Delete 屏蔽、原始/处理后选区播放、移动/resize、重叠对象选取、菜单边缘定位及键盘操作。输入框 Delete/空格/Ctrl+Z 不误操作音频；关闭/另存期间动作不越过屏障。
