# 拖放导入与目录树移动设计

2026-11-09 · Windows 桌面版

## 范围

从 Windows 资源管理器拖入普通音频、音频 ZIP 或文件夹。普通音频沿用直接导入，ZIP 和文件夹自动扫描，用户在现有预览中确认布局后导入。在左侧目录树中，拖放可以移动单条或整批勾选的音频。

设计选用现有入口分流。普通音频复用直接导入任务，ZIP 和文件夹复用来源导入窗口，目录树移动复用共享目录提交。统一导入清单可以集中处理混合来源，但需要额外的任务队列和交互页面。

## 从资源管理器拖入

| 来源 | 单次拖入范围 | 松手后的行为 |
| --- | --- | --- |
| 普通音频 | 一条或多条现有支持的 WAV、FLAC、MP3 | 按现有直接导入流程开始，显示导入进度和结果 |
| 音频 ZIP | 一个或多个 ZIP，沿用现有来源数量上限 | 带入来源和当前导入设置，打开现有窗口并自动扫描，等待确认 |
| 文件夹 | 一个文件夹 | 带入来源和当前导入设置，打开现有窗口并自动扫描，等待确认 |

- 拖到目录树的文件夹行时，该文件夹成为目标。拖到「全部音频」行时使用根目录。窗口其余工作区沿用当前导入目标，未选定目录时使用根目录。拖动中高亮可接收的目标，松手时以实际命中的目标为准。
- 松手后由原生工作线程检查来源类型。目录以实际文件系统类型判定，扩展名按现有规则识别。一次拖放含混合类型、多个文件夹、不支持的文件、无法读取的来源或超出已有上限时，在开始导入或扫描前提示分开拖入或修正来源。项目分享包沿用「导入分享文件…」入口，拖入带 `.audioproj.zip` 后缀的文件时提示使用该入口。
- 文件夹和 ZIP 保留现有导入预设、扫描问题、布局预览、去重及确认动作。调整规则或目标后须重新扫描。确认前取消会结束该扫描。写入阶段沿用已有任务取消和失败重试规则，已提交的音频保留。
- 未打开项目时提示先打开或新建项目。只读、已有导入占用、项目正在切换、模态窗口覆盖工作区时，显示相应拒绝原因。普通项目可使用现有的直接音频导入能力，ZIP 和文件夹需要支持来源扫描的可写协作项目。
- 系统拖动进入窗口时绑定项目会话。会话切换后取消该次拖动，直到下一次进入事件。松手时记录命中的目标目录 ID 及布局版本 `layoutRevision`。直接导入和 ZIP、文件夹的首次扫描都使用这份目标快照。目标失效或布局版本变化时提示核对目标，用户重新拖入或在来源导入窗口核对后重新扫描。显式重新扫描时使用经核对的最新布局。
- 路径预检及后续任务启动均校验原生会话代数和导入权限，普通项目也适用。预检结果与发起会话绑定，同一个项目 UUID 关闭再打开后使用新的会话代数。界面在预检完成后同时核对当前项目拥有者，避免旧拖动结果进入新会话。

## 在左侧目录树移动音频

- 正常音频的目录树行作为拖动起点。拖住已勾选的音频时，以开始拖动时的全部勾选音频 ID 为本批范围。拖住未勾选的音频时，本批只含这一条。可放到任意可接收的文件夹行或「全部音频」根行。文件夹本身仍可通过现有菜单整理。
- 达到拖动阈值才开始显示目标反馈，以便普通点击继续选择音频。目标行高亮并提示移动数量。松手到有效目标立即提交。按 Escape、离开后取消、放在无效区域，或整批已在目标目录时，结束手势并清除提示。只读、回收站视图及已有目录修改正在提交时禁用移动。
- 整批移动保留音频 UUID、原始文件名、已有标注与播放选择，通过更新各音频的 `folderId` 改变共享目录归属。已在目标目录的条目算作本批已满足。提交完成后刷新计数、展开目标祖先，并把焦点移到目标行。列表继续使用现有排序规则。
- 在开始拖动时记录目录 `revision` 和项目会话。Rust 在现有共享目录提交锁下校验会话、写入权限、目录版本、目标目录、所有音频 ID 及最新回收状态。确有归属变化时，一次替换组织文件并各推进 `revision` 和 `layoutRevision` 一次。整批已在目标目录时返回当前目录。任一条目不可移动或发布失败时整批失败，两个版本均保留。若提交结果不明，先刷新目录并核对批次状态，再允许用户重试。
- 遇到版本冲突时刷新目录，保留原批音频 ID 和目标供用户核对。目标与全部源条目仍有效时，用户可用刷新后的版本显式重试。目标失效时提示重新选择目标，源条目失效时提示重新选择要移动的音频。只有确认当前会话和操作对象后才允许重试。

## 实现边界

- 外部拖放使用 Tauri 的 WebView 原生文件事件，保持 Windows 原生文件拖入能力。进入时记录项目会话，进入、移动和离开事件更新手势状态及目标提示。命中测试将事件的 WebView 物理像素坐标转换为 CSS 像素，再判定目录行。路径分类和有效性验证在松手后运行，复用文件导入侧的路径安全与格式检查。识别后的来源分别交给现有音频导入和来源扫描控制器，按已有任务占用和会话规则处理。
- 内部拖动由目录树的指针手势处理。它携带当前会话的音频 ID，使用同一套目录目标命中规则。这样 WebView2 可以保留原生文件拖放处理，目录树手势也可以直接由界面识别。手势结束、窗口失焦或会话切换时释放指针并清除提示。
- 共享目录操作增加批量移动请求。目录树拖动单条时也提交含一个音频 ID 的批量请求，以统一手势中的回收状态检查和同目录处理。现有菜单使用原单条移动请求，沿用已有的可移动范围。两种请求复用成员校验和目录事务，按各自的操作规则验证。批量写入使用现有的组织文件格式、原子发布和错误反馈。

## Compatibility / Migration

| 项目 | 约定 |
| --- | --- |
| Backward compatibility | Required |
| Protected surfaces | 已有项目和共享目录文件格式、音频 UUID 和标注关联、导入预设、音频与 ZIP 的格式限制、原菜单入口及单条移动请求 |
| Allowed breakage | 无 |
| Migration strategy | None。批量移动请求仅扩展客户端操作，发布的目录文件仍可由现有兼容客户端读取。 |

## 验收

1. 在 Windows 从资源管理器实际拖入单条与多条普通音频、单个文件夹、单个与多个音频 ZIP。验证指定目录、根目录、当前目标及高 DPI 显示下的命中。普通音频立即出现进度，ZIP 与文件夹进入可确认的扫描预览。
2. 验证混合来源、多个文件夹、分享包、不可读来源、未打开项目、只读会话、导入占用和模态窗口的反馈。普通项目可拖入音频，拖入 ZIP 或文件夹时得到需要可写协作项目的提示。取消预览时核对目录和音频清单。
3. 在外部拖动期间切换项目，在延迟预检期间关闭并重新打开同一 UUID。核对旧会话请求被拒绝。在 ZIP 或文件夹松手后、首次扫描前改名或移动目标目录，验证扫描报告布局冲突，用户核对后可显式重新扫描。
4. 验证普通点击、内部拖放单条、拖住勾选项移动整批、拖住未勾选项只移动该条、移到根目录、拖到原目录和取消手势。按 Escape 或失去指针捕获时，清除提示并保留播放选择。核对新目录、排序及原音频 ID 与标注关联。
5. 用两个协作会话覆盖拖动期间目录改动、目标删除和目录写入失败。单独验证另一会话仅把一条源音频放入回收站，目录 `revision` 未推进，拖动整批仍被拒绝。一个有效批次包含已在目标的条目时，两个版本各推进一次。整批已在目标和发布失败两种情况的版本均与提交前一致。核对显式重试和另一会话刷新后的目录。
6. 回归现有菜单导入、单条目录移动（含回收站视图）和多选导出。实际导入或移动验收使用专用测试项目，核对已有项目可打开且目录格式兼容。
