# 随机打开未分类音频快捷键

日期：2026-10-28

## 目标与已确认行为

本次新增导航功能：增加单键 `R`，随机打开当前列表范围内的一条未分类音频。打开后不自动播放，用户可按空格试听，或继续分类和其他现有操作。

用户最终确认按标签判断资格：当前作者的文件标签、所有通道标签、所有局部区域标签均为空，才算本功能的“未分类”。文件、任一通道或任一局部区域有标签，都排除整条音频。仅画了没有标签的区域框不影响资格；备注、私人屏蔽和区域增益也不作为分类依据。他人的标签不影响本人的候选。

其他已确认选择：使用 `R`；遵循当前目录、搜索和筛选；有其他候选时避免连续打开当前音频；不维护抽取历史；保留现有兼容性和现有“未标注”筛选含义。

## 当前实现与范围

- 左侧列表通过应用壳层选择主面板，选择成功后调用播放源选择；上下键导航也复用此入口。随机打开复用这一选择与播放源协调能力。
- 用户已确认现有代码已完成空格播放修复。本次复用现有播放/暂停能力，仅验证随机打开后与该能力的衔接。
- 现有列表范围包含目录、子目录、搜索、标签及标注状态筛选；折叠状态只影响展示，不缩小导航范围。现有“未标注”会排除任何区域标注，与本功能按局部标签判断的规则不同，保持原有筛选语义。
- 主面板和对比面板不允许显示同一音频，随机打开需要遵守这一约束。

## 方案选择与职责

采用局部扩展音频列表导航的方案。列表已有构造候选范围、展开目录、焦点移动和滚动的能力，复用它们可使 `R` 与当前浏览条件一致；应用壳层继续负责工作区选择和播放源协调；播放模块继续负责播放意图、异步命令、暂停及错误反馈。

另一方案是在应用壳层统一集中所有键盘命令，需要上提列表筛选状态并调整多个现有快捷键入口。它对统一管理有帮助，但本次新增随机导航无需这种重构，因此不采用。

候选判断和随机选择可提取小型纯函数，随机源可在测试中控制。生产环境对本次有效候选等概率抽取，不新增持久化配置、公共 IPC、文件字段或用户自定义按键功能。

## 随机打开规则

1. `R` 仅在活动项目允许现有音频导航、列表处于“正常音频”视图时生效。未打开项目、项目切换/关闭或工作区转换禁止操作时不触发。导入期间沿用现有导航准入，不能仅因导入按钮禁用就禁止试听导航。
2. 从当前列表已应用目录（含子目录）、搜索、标签、标注状态及“搜索整个项目”选项后的结果中，再按上述未分类定义取交集。不自动清空或改写任何筛选条件。
3. 排除本人隐藏、共享回收站、已在对比面板显示的音频，以及媒体状态明确为 `missing` 或 `changed` 的音频。`ready`、`unverified` 和尚无状态记录的音频允许参与；实际不可用时由现有播放边界报告。
4. 有非当前音频的候选时，先排除当前主面板音频，再随机取一条。每次独立抽取，先前打开但仍未分类的音频可再次出现。
5. 没有任何候选时，不改变选择、播放源、焦点或播放状态，通过可访问状态提示“当前范围内没有未分类音频”。仅当前主面板音频符合时，同样保持状态，提示“没有其他未分类音频”。不通过重新选择当前音频来停止或重置播放。
6. 成功抽取时复用现有左侧音频选择入口：打开主面板，设为播放源并停止旧播放，不启动新播放；展开目标祖先目录，滚动到目标并聚焦其音频条目。随后空格应播放新音频。已有标注、标签、备注、私人编辑和批量勾选集合不因随机预览而被编辑。
7. 资格使用当前作者最新文档计算。分类、撤销、移除标签、目录/搜索/筛选变化、状态刷新及项目/身份切换后，下次按键立即依据最新状态重新计算，不缓存旧候选结果。
8. 延迟的焦点和滚动回调必须属于仍有效的项目/身份与最新导航意图；项目关闭、更换或后续操作取代它时，不得夺回焦点或作用于新项目。组件卸载后释放监听与局部状态。

## 键盘与播放交互

`R` 作为无修饰键的单键命令处理，大小写字符等价；不接收 Ctrl、Meta、Alt、Shift 组合。忽略输入法组合输入、长按重复事件和已被其他控件处理的事件。

文本输入、下拉框、可编辑内容、菜单、菜单栏、对话框、滑块、分隔条及页签控件保留自身键盘行为。菜单打开时不触发 `R`。普通工作区及音频条目可触发；多选模式中的随机预览不改变勾选集合，复选框本身保留原有操作。

随机打开后保留现有选区、播放起点和声音版本规则。通过“R 打开目标 → 空格试听”的连续操作，验证新导航与现有播放入口衔接正确。

## 错误、状态与代码约束

空候选和仅当前候选是正常导航结果，不抛异常；提示由当前列表实例持有，新的随机操作或项目/身份上下文变化后替换或清除，不向其他实例泄漏。

工作区选择未成功时，不更改播放源，也不把失败当成成功聚焦。候选过滤不是后台状态验证的替代；播放准备、解码和输出失败继续由现有 `usePlayback` / 播放栏错误边界规范化和展示，并保留现有重试路径。不得自动抽另一条掩盖播放失败。

新增异常必须具有明确语义、诊断或恢复价值。禁止无理由的宽泛捕获、静默回退，以及对已规范化错误的重复防御包装。确定性的候选计算不新增异常捕获。

候选、导航意图及提示由组件或实例拥有，不增加模块级可变单例。禁止仅使用一次的模块级常量，除非代表稳定外部协议、文件格式、环境变量名、CLI/API 合同、模式字段或序列化/外部可见状态值；稳定边界仅局部使用时可留在模块内，需要跨测试、文档或多个模块稳定引用时放入符合项目惯例的 `consts` 目录。其他值使用局部变量或内联字面量。不进行无关重构。

- Backward compatibility: required
- Protected surfaces: [项目及作者层格式、原生 IPC/API、现有快捷键、文件/通道/局部标签和备注、现有“未标注”筛选、目录/搜索/筛选状态、隐藏与回收站、作者隔离、批量勾选、播放与选区规则、保存/同步和撤销历史]
- Allowed breakage: [无；仅新增 R 随机打开命令及其状态提示]
- Migration strategy: none

不增加格式版本、迁移脚本、兼容层或弃用窗口。更新应用内快捷键帮助与使用说明，明确 `R` 的范围、按三层标签判定的资格及手动播放行为。

## 验收与验证

1. 文件有标签、任一通道有标签、任一区域有局部标签分别排除；仅有无标签区域框、仅备注或私人处理仍符合资格。他人标签不排除本人候选。加标签、移除最后一个标签及撤销后资格实时更新。
2. 目录及子目录、搜索和各筛选组合遵循当前列表结果；折叠目录内的候选仍可抽取，打开后展开、可见并有焦点。现有“未标注”筛选保持原义，即使因此排除了仅有无标签区域框的音频。
3. 隐藏、回收站、对比面板占用和已知缺失/变化音频不能被抽到；未验证和暂无状态的候选可抽取。之后若播放失败，显示原有错误与重试，不暗中换文件。
4. 用可控随机源覆盖多个候选及不同抽取位置；多次按 R 避免连续同条但允许历史重复。零候选、只有当前候选时提示正确，选择和已有播放不中断；只有一条非当前候选时直接打开它。
5. 无修饰键 R 打开一次，长按不反复切换；修饰组合、输入法、输入控件、菜单、对话框及已处理事件均受保护。随机打开后不自动播放，下一次空格通过现有入口播放新音频。
6. 多选模式保留勾选，导入期间保留现有导航能力；项目转换禁用时不执行。项目/身份切换和后续导航取代旧请求时，迟到回调不夺回焦点、不使用旧候选。

验证以随机导航、列表、工作区及现有播放入口的实际集成为主。实施阶段运行相关前端测试、完整 `npm test` 和 `npm run build`（包含类型检查）；使用当前源码构建的桌面应用执行“R → 聚焦新条目 → 空格试听 → 分类 → R”的连续流程。若桌面验证不可执行，应明确报告验证范围及未验证项，不能把组件测试等同于实际桌面验证结论。
