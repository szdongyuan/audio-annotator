# Project-scoped example audio

## Approved product boundary

The user requests named example audio (OK1, OK2, NG1, 转动异常), private and shared lists inside each project, removal of the inspector Device tab, and an output-device settings dialog without submitted-frame or underrun diagnostics. The user explicitly clarified that examples do not follow the user across projects: another project requires another import. Earlier authorization permits autonomous completion without spec approval requests.

## Behavior and layout

Replace the inspector's Device tab with 示例. Show two compact scopes, 我的示例 and 共享示例, plus an import action and name search. Rows show the custom name and a small play control; use contextual menus for rename, remove, copy to the other scope, and viewing the spectrum. Import supports existing supported WAV/FLAC/MP3, defaults to original filename without extension, and accepts a friendly name without renaming the source file. Users can also add the currently selected project audio as an example so an existing OK/NG is easy to retain. Names may duplicate: UUIDs identify records.

Examples belong to the current project and never inflate the ordinary audio list, annotation counts, directory counts, or shared annotation layers. Private entries belong to the current project and current UUID identity in app-local storage. Shared entries and their original audio bytes reside inside the shared project so another workstation needs no original source path. Switching project or identity clears the previous scope and closes its preview. Shared entries display their creator; everyone can read/play them, only the creator may rename/remove their entry. Concurrent authors cannot overwrite each other's entries. Copying creates a separate record; removing one scope does not remove the other copy.

Clicking the name or 查看频谱 opens a focused read-only example preview, showing channels and the existing spectrogram rendering with the current local analysis/display defaults. It permits zoom/pan and listening, but creates no annotations, masks, project media or shared preferences. Main audio and examples use one output device at a time; switching to preview stops the previous source. Closing preview stops sample sound and releases analysis leases; it does not change the selected main file or its labels. Preview may show channel selection rather than squeezing six spectrograms into one modal. Expose play/pause/stop, seek and duration, with current private monitor gain and volume applied. If implementing comparison, show the selected project audio and the sample side by side inside the preview; comparison is optional for this increment, a working spectrum viewer and audition are required.

The existing 音频 → 输出设备… menu opens a small modal instead of changing inspector tabs. Also include 输出设备… in the bottom playback-bar menu (the user's screenshot is the audio menu, both entries should reach the same dialog). The dialog contains the device selector, system default and refresh; selection updates private playback preferences. Remove submitted-frame/underrun counters from product UI, retaining internal telemetry/API as needed. Click outside or Escape closes the dialog, focus returns to the trigger, and narrow layouts retain all inspector tabs.

## Storage and authority

Add a separately versioned example-library sidecar; do not change existing ProjectDocument, collaboration manifest, author-layer or exchange versions. Absence means an empty library and read-only opening must not create files. Use original-byte copies into owned scope roots with UUID-derived paths, content fingerprints and supported extension validation, not references to arbitrary external paths. Keep private media beneath the app-local private project workspace; shared media beneath a dedicated project examples directory. Author-owned metadata files or a properly locked revisioned store must handle NAS concurrency, optimistic conflicts and atomic persistence. Do not follow links/junctions or trust user-provided stored paths; use the project's existing safe path/file helpers where possible.

Metadata must bind project UUID, actor UUID, sample UUID, name, media identity and scope. Validate finite bounds, supported channel counts and original source hash before decoding or previewing. Import/copy returns durable success only after audio and metadata are committed; failures retain earlier entries and remove only owned new temporary files. Clear error + retry on NAS failures. Empty/overlong names are rejected without losing the edited input. Bound entries (1000 per scope/author), batch sizes and decoded resources; reuse the bounded PCM/tile pipelines rather than sending complete PCM over IPC. A missing/corrupted shared example produces an item error without corrupting the main project.

Native commands capture the current runtime nonce/project/actor before I/O and recheck before publishing. Private imports must not write into shared catalog or annotation layers. Shared reads work for guests; mutations require an active identity and follow existing project read/write capabilities. Private scope is disabled for guests without a stable identity. Preview uses separate transient media authority and existing decode/DSP/FFT rendering rather than injecting sample media into the ordinary project. A superseded preview or stale response cannot control or publish into the new project. Reuse the singleton audio output so simultaneous devices/streams do not overlap unexpectedly.

Examples persist across restart and moving/reopening the shared folder; shared original bytes are included naturally when the whole shared project folder is copied. Existing annotation/project exchange semantics are unchanged in this increment: do not silently export private samples. Documentation must state that sharing examples uses the shared project folder; legacy annotation/project exchange packages do not carry this new library.

## Compatibility / Migration

- Backward compatibility: required.
- Protected surfaces: existing project/audio/annotation/identity/private settings files, default and legacy projects, original audio, existing playback and spectrogram APIs.
- Allowed breakage: removal of Device inspector tab and public diagnostics, replaced by the device dialog; new optional sidecar/commands.
- Migration strategy: none; optional new sidecar starts absent. Older clients ignore it. Keep version 0.7.4 during development, then prepare a 0.7.5 local test candidate after integration verification. Deliver the installer/update to the user's existing software directory on NAS, preserving the 0.7.4 candidate. No GitHub Release or updating PR #3 in this increment.
