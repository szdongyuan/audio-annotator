# Shared folders and organized import/export design

Date: 2026-10-26. User approved both a shared project folder tree and directory-preserving export, plus meaningful import presets with collapsed advanced controls. Earlier autonomous authorization remains: implement without spec approval pauses. Existing source NAS archives/projects and all old releases are read-only during development. No data migration is required.

## 1. Outcome and scope
- All current writable shared projects have one persistent project folder tree shared by authors. Stable folder IDs, parent IDs and media UUID membership are independent of each author's labels, notes, masks, volume, hidden list, history and selection.
- Create, rename, move and remove empty folders; move an audio into a folder. Moving a folder moves its descendants logically. No physical relocation/deletion of original or catalog audio. Root is implicit, cannot be renamed/moved/deleted. Folder removal refuses children or assigned media, including media hidden in this client.
- Import plans combine discovery and organization. Built-ins produce visibly different layouts; ordinary use does not require patterns/templates. Advanced discovery, naming and custom-preset controls are collapsed by default. Native scan preview shows resulting project paths.
- Bundle export offers checked-by-default '保留目录结构'. ZIP audio entries use actual planned directories and original filenames/extensions; logical folder metadata always roundtrips, even when audio entries are flattened. Existing annotation-only export carries organization without audio. This extends the existing project ZIP, not a second raw-audio export workflow.
- Preserve default UUID collaboration, two-file spectral work, per-author labels, private settings, immutable audio identities and recovery. No server, accounts, scripting language, inferred annotation labels, full team backup or hardcoded N: source shortcuts.

## 2. Chosen architecture and compatibility
A bounded roundtable (Customer Advocate, Optimization Architect, YAGNI Minimalist) preferred an independent shared organization snapshot over embedding folders in private ProjectDocument or deriving them from displayName. The architect identified the two-file commit window. We choose a shared organization head as the single publication point: immutable audio/catalog records are staged first; atomic head replacement makes media and placement visible together. The minimalist's simpler root-placement fallback is rejected because an acknowledged preset import must not silently lose its placement.

- Collaboration format becomes 4, catalog version becomes 2, immutable media-record envelope remains version 1. Required organization.json is kind audio-annotator-organization, formatVersion 1 and bound to projectId.
- Organization head: {kind,formatVersion,projectId,revision,layoutRevision,folders:[{id,parentId:null|UUID,name}],media:[{mediaId,folderId:null|UUID,originalFilename}]}.
- The media list is also committed catalog membership. Readers expose only catalog IDs referenced by the captured head. Every referenced catalog record and raw media must exist and validate; no membership is guessed from orphan files. Read each head through one bounded handle and use that immutable capture to load its catalog; do not reread a newer head midway.
- ProjectDocument remains version 2 and contains no shared folder fields. Open/status/organization commands carry a separate validated OrganizationSnapshot, bound to runtimeNonce and projectId; personal undo/save never publishes organization.
- Exchange format becomes 3, carrying organization and export layout independently of ProjectDocument2. Old collaboration formats 1/2/3 and exchange 1/2 are rejected early without rewriting bytes. Prior app/releases remain available. Existing ordinary ProjectDocument2 open/save behavior remains protected; ordinary projects display a root list and can create a collaboration copy to gain shared editing. Ordinary exports create a root organization in exchange3. Standalone exchange snapshots are rebound to the importing/copy project; the wire organization projectId must match the exported manifest projectId.
- New/imported/copied shared projects initialize a complete organization head. Save As/personal copy preserves folder nodes and filenames, including empty folders and hidden media, while retaining existing author/private-state scope. Copy/export media scope remains the captured personal document, including its hidden media; pending remote media not yet explicitly adopted are not silently added. Filter organization membership to exactly the copied/exported media IDs while retaining folder nodes, so the new target head has no foreign/uncommitted references. Exchange import rebinds organization to the new project ID, retaining media/folder IDs and user's own imported labels.
- Backward compatibility: partial. Protected surfaces: ordinary ProjectDocument2, UUID profiles/identity transfer, label ownership, private workspaces, audio bytes, basic playback and analysis. Allowed breakage: prior collaboration/exchange versions and local import-preset storage. Migration strategy: none; new preset key v2 leaves old local values untouched.

## 3. Organization invariants and publication
- At most 10000 media and 10000 folders, 16 folder levels, 16 MiB serialized head. UUIDs canonical/nonnil and unique; every media ID appears exactly once, every folder reference exists, tree acyclic/reachable from root. Sibling names unique under Unicode lowercase comparison. Name: trimmed 1-128 Unicode scalar values, <=512 UTF-8 bytes, no C0/C1 controls, slash/backslash, '.' or '..'. Other characters may be retained logically and sanitized on export.
- originalFilename is one nonempty basename including its original extension: 1-255 Unicode scalar values, <=1024 UTF-8 bytes, no separators/controls. It is captured natively from the source filename/ZIP entry, not caller-provided displayName. Legacy ordinary copy may use its existing native-generated displayName last component with deterministic UUID fallback and the existing verified-byte extension detection when necessary. Store raw displayName/source provenance separately as today.
- revisions are monotonic safe integers. revision advances on every head commit. layoutRevision advances on manual folder/membership edits, not additive import publication. Thus concurrent additive imports can resolve the same target path under the lock, while manual reorganization invalidates existing placement previews.
- Core repository organization mutations take expected revision under the same short interprocess mutation lock as catalog publication. Stale mutations return Conflict/current revision; no automatic stale overwrite or merge. Read-only actors cannot mutate. Native guards check project/runtime/author lease and existing service admission/recovery; folder edits do not require saving or replacing personal annotation documents.
- Import scan seals {layoutRevision,targetFolderId,relativeFolderSegments,originalFilename} with the native task/candidate and prepared capability. The client cannot authorize arbitrary catalog placement through a descriptor. At commit, reject changed layoutRevision/missing target, resolve/create the sealed path in the current head, reuse same-named existing groups, add only ancestors needed by that accepted media, then atomically publish the new head last.
- Publication sequence under lock: capture/validate head+catalog; validate sealed placement; place owned raw audio and immutable record; construct/size-check next head; atomic replace head. Only then return success/adopt into private workspace. On a precommit error retain the prior head; clean only owned uncommitted artifacts when possible. Once atomic head replacement completes, the commit is final even if its acknowledgement is lost or a late cancellation arrives; never roll back visible media/placement. Retry must acknowledge that committed state. Crash leftovers remain invisible and are never guessed as committed media.
- Ignore well-formed unreferenced UUID catalog records when reading; retain bounded enumeration (100000 total entries) and reject links/unknown unsafe shapes. Never mutate/delete orphan artifacts during a read. New writers may clean only their own known staging files; no broad orphan deletion.
- Retry after head commit recognizes the existing media UUID and original committed placement; it does not duplicate/import again or replay an old path after another author moved it. Existing native import acknowledgement/recovery machinery remains reachable.
- Source changes, size/field errors and changed layoutRevision are explicit preflight/commit errors. Import cancellation preserves accepted media and their folders, adds no folders for unaccepted media, and releases retained capabilities normally. Invalid/corrupt/missing required head fails closed without replacement.

## 4. Import plans and advanced controls
- Discovery retains generic and jingcheng-run-export-record/v2 semantics, recursive/ext/include/exclude settings and logical includeSecond. Discovery 'all' does not parse result metadata; jingcheng requires valid route manifests as today. No inference that CH1 is always logical route1.
- Config adds organization {targetFolderId:null|UUID,mode:'sourcePath'|'flat'|'template',wrapSource:boolean,stripComponents:string[],template:string}. targetFolderId binds current shared folder; default root.
- Template is a slash-delimited list of literal segments and exact whole-segment tokens {source},{relativeDir},{record},{date},{result},{faultType},{model},{route}. {relativeDir} may expand multiple directory components; all other tokens expand one. No regex replacement, arbitrary JSON query, code or embedded token expressions. Reject unsupported/braced tokens or dot/empty/absolute segments before scan. With generic discovery only {source} and {relativeDir} are permitted; {record}, {date}, {result}, {faultType}, {model} and {route} require jingcheng discovery and are rejected before scan otherwise. The advanced token picker shows only supported tokens.
- source = selected folder or archive stem; relativeDir = candidate parent directory; stripComponents removes exact case-insensitive named directory components from that source-relative path only. record = containing valid manifest directory basename. date = date portion of valid run.accepted_at; result/faultType/model = outcome.result/outcome.fault_type/run.model, trimmed bounded strings; route = 第一路/第二路 from position. Metadata separators become underscores to keep one segment.
- Missing optional metadata uses 日期未知 / 未分类 / 型号未知 / 记录未知 as appropriate and emits a bounded scan issue while retaining the candidate. Required route/manifest errors still exclude invalid jingcheng candidates. Overlong/invalid generated paths are reported and excluded; never silently truncate logical organization. Keep source timestamps/paths/content read-only.
- Built-ins: 通用·保留来源目录 (generic/sourcePath/wrapSource true), 通用·平铺 (generic/flat), 精成·按结果和故障分类 (jingcheng/template {source}/{result}/{faultType}/{record}), 精成·保留来源目录 (jingcheng/sourcePath/wrapSource true/stripComponents ['audio']). Generic presets do not offer the logical second-route toggle. Exact discovery/layout summaries are visible via controls/compact selected summary, not permanent explanatory banners.
- Visible compact form: source picker, 导入方案, target folder, layout choice, relevant second-route toggle, 扫描预览 and explicit 导入 N 个音频. Advanced disclosure contains parser selection, include/exclude patterns, recursion/extensions, source wrapping/strip components/template, custom plan save/delete. Built-in choices can be customized without overwriting them; custom plans store discovery+organization together in v2 local storage, max32, matching bounded serialization/reader budgets. Never persist absolute source paths. Presets persist reusable discovery and organization rules, excluding targetFolderId: that UUID belongs to the current project context. Applying a built-in/custom preset retains the currently chosen target folder; initial dialog entry uses the selected project folder or root. Only local presets are personal; imported folder assignments are shared.
- Changing any plan/target setting invalidates the old preview and releases its native token, preserving existing failure/recovery semantics. Form values reflect actual current config rather than stale useState copies. Preview displays a bounded expandable resulting tree and selected-file details/original source path; <=50 visible media rows/page, aggregate counts, explicitly labeled missing-field issues. Build tree incrementally/index once per scan snapshot, not O(n²) every render.
- Direct file import goes into selected target folder (root if none); source/folder import uses selected plan. Existing direct/relink paths and ordinary-project import continue to work. Relink never changes folder membership or original filename metadata.

## 5. Tree UI and synchronization
- Replace the flat shared media area with a compact expandable tree, folder counts and root entry '全部音频'. Search matches names and project folder paths, reveals matching ancestors, and preserves source-context accessibility names. Existing audio metadata, missing-source actions, per-author hidden list and selected/playing state remain.
- Folder context menu offers create subfolder/rename/move/remove-empty; media context offers move to folder alongside existing hide/relink actions. Use native-authoritative operations, keyboard-accessible dialogs, Escape/outside dismissal and stable return-focus targets before app inert. Drag/drop and multi-selection are not required this release.
- Folder selection scopes the list/import target; folder IDs keep selection stable across renames/moves. Selected playing media remains active on moving it or receiving a remote folder update. Removed selected empty folder falls back to root. Hidden media still counts for nonempty-removal validation.
- Separate organization controller/hook/store, keyed by active owner+runtimeNonce, polls at current collaboration cadence (1500ms) and on focus. It updates only organization DTO state; it never calls project/catalog adoption, saves a draft, clears selection/history, rebinds playback or releases PCM. Stale generations and replaced owners cannot install a late response.
- Shared organization can include newly published media not yet adopted by this client's personal catalog. Display only known media IDs, leave existing explicit 更新音频列表 behavior in place, and retain folder context for later adoption. Folder-only updates do not show a fake media-catalog change.
- Concurrent mutation conflict retains user dialog input and reloads latest tree, with explicit retry. Missing/corrupt head errors retain last valid UI snapshot and show an actionable error; no destructive fallback. Native get/apply responses include current snapshot/revision and runtime binding.
- Ordinary legacy projects retain their root flat-list semantics; shared folder mutation controls are unavailable until creating a collaboration copy. Read-only shared projects show synchronized tree but mutation controls disabled.

## 6. Export/import
- One pure native ExportPathPlan is used by preview and writer. It is derived from the captured organization, current adopted document media and preserveFolders, not client-selected paths. Preview carries runtime/project/document/organization revision; start rechecks these and fails stale before publishing output.
- Exchange3 manifest contains organization (logical names/IDs, media membership/originalFilename), preserveFolders and actual validated mediaPath for bundled media. Annotation-only paths are null. It may include empty folders and new media not adopted? No: filter membership to exported document media and retain the folder tree including explicit empty folders; all references validate. Exporting the current author's content does not export others' annotation layers/private settings, preserving existing scope.
- Audio entries live below audio/. preserve=true uses current logical folder hierarchy; preserve=false places filenames directly under audio/. Preserve bytes, hash checks, cancellation, limits and create-new/no-clobber publication. Empty logical folders are represented in bundle metadata and as ZIP directory entries when preserving.
- Sanitize each export component: invalid Windows characters/controls to underscore, trim trailing dots/spaces, prefix reserved device names; bounded shortening of >120 UTF-16-unit components with stable ID suffix. Detect case-insensitive collisions (Unicode lowercase); resolve deterministically using full stable folder/media UUID suffix, with a second uniqueness check. Reserve sibling folder names and audio filenames in the same collision namespace, including file-versus-directory collisions. Same-named audio never overwrites/deduplicates. Logical names/IDs remain exact in metadata.
- Planned archive paths must be relative, safe and <=240 UTF-16 units; too-deep/long output fails with a path-specific preflight error (user can shorten folders or choose flat). Keep all paths under audio/, excluding manifest/control-file collisions. Export preview lists original->planned path for any change; path warnings/details are collapsed, not a permanent banner.
- Exchange3 ZIP paths are bounded UTF-8 Unicode, permitting Chinese names (replace the old ASCII-only exchange path check). Directory entry trailing slash is permitted only for a declared directory; strip exactly that suffix for component validation. Raw central-record preflight still occurs before ZIP index allocation. Exchange limits: 32 MiB manifest, 20002 raw entries (10000 audio + 10000 folders + manifest + audio root), existing 20 GiB total and 8 GiB per media. Writers/readers/planner use these same budgets.
- Import verifies manifest version/tree/IDs/bounds and recomputes expected safe paths exactly using the same planner. Reject undeclared/missing/duplicate/case-colliding/traversing entries, malformed directories and raw-byte mismatches. Extract only to owned UUID staging, not business directories in the live NAS project; then create a new format4 project with organization and the selected identity. Cancel/errors clean only owned destinations and keep the current project intact.
- SaveAs/copy use current consistent organization with all source media and existing private-state semantics; source tree/audio unchanged. No per-author labels inferred from directory names. Directory updates after export starts do not modify the already captured output; start must match the accepted preview revision.
