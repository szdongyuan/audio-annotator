# 默认协作项目设计

## 1. 目标与授权

用户提出单人标注是协作的特殊情况，要求协作成为默认行为。延续上一轮“独立自动完成，无需批准 spec”的授权。本轮由代理完成设计、实现和验证，不新增审批。新项目无需先建立普通项目再创建协作副本；本机目录和 NAS 目录使用同一作者隔离模型。继续支持 Windows、1–6 通道、现有频谱和选择操作。界面保持紧凑。

采用共享项目作为默认后端、自动本机作者、可追加公共媒体。仅把“创建协作副本”变成向导默认项仍留下双流程和访客不共享问题，不采用；去掉作者权限让所有人写同一个 JSON 会覆盖标注，不采用。旧普通项目实现作为显式旧文件读取/交换中间格式保留，不进行无关删除重构。

## 2. 默认作者

新建或打开新版项目时，默认使用该 Windows 用户在本机的稳定身份，无需注册或输入密码。该身份是正式作者，标注正常发布到项目；UI 显示“本机作者 · 短标识”，可通过紧凑身份菜单切换到已有项目账号或注册账号。登录可选；退出账号返回本机作者，不再默认进入未共享的访客编辑状态。不同机器/Windows 用户默认获得不同身份，重复标注保持独立。

本机身份使用随机生成的账号凭据和既有作者锁/Argon2 权限路径，保存在应用本机数据目录；Windows DPAPI CurrentUser 加密随机秘密，绝不放到项目、ZIP、IPC 返回、日志或公共状态。身份初始化须原子、并发幂等，先可靠持久化本机凭据再注册公共账号；重试不得制造新作者。损坏/解密失败明确报错，不静默换作者。默认身份账号名使用预留随机命名空间，显示短标识不暴露 Windows 用户名。保留项目内显式账号登录语义，不存储用户输入密码；正式账号切换不自动认领/复制本机作者历史。指南说明在另一台电脑继续同一身份需使用项目账号，默认作者属于该设备用户。无需身份云服务、自动账号合并或身份迁移。

打开只读目录或本机作者已被另一实例锁定时，允许明确的只读查看入口；不得静默获得另一作者写权限或把未发布编辑表现为共享成功。查看身份不提供标注写入，播放/本机设置可继续。已有旧协作格式访客流程可继续作为兼容读取，不改变旧版证据与发布文件。

## 3. 可追加媒体

新版项目清单保持固定项目身份；以受验证的追加式媒体目录记录扩展音频列表。每个媒体记录不可变，文件名由 UUID 派生，音频复制并验证完成后才发布目录记录。并发追加不同媒体互不覆盖；同一源重复导入沿用现有指纹判重规则，不按标注内容去重。临时文件不可见，失败只清理本次拥有的未发布文件。所有路径、大小、枚举数、指纹和 1–6 通道约束延续原合同。未知格式 fail closed；新版清单/目录有明确格式版本，旧程序不能误写。

所有已认证作者（含自动本机作者）可导入音频/文件夹；导入仍有进度、逐项错误、取消和重试。普通 ImportMedia DTO 不能绕过 native 验证直接插入公共媒体。共享 I/O 不持有全局项目/播放锁；捕获 runtime/actor，旧任务不能污染新项目。发布前须保证本次媒体确实已确认导入，取消不得遗留已发布但前端表示失败的隐形副作用；已完成项在取消后保留并如实报告。

媒体目录更新不得破坏作者旧快照：旧层可只含当时存在的媒体标签；新增媒体默认无标签。已有媒体的身份/元数据不可被修改或替换。每个作者本机 envelope 根据追加目录扩展，保留原备注、pending、confirmed、in-flight、音量、屏蔽、视图和恢复信息；历史中的个人文档也须保留公共媒体，撤销不能撤销他人的媒体追加。恢复候选同样受目录升级规则验证，不能自动放弃待恢复数据。

本机导入完成立即显示。其他客户端发现新增媒体后，在协作状态菜单提供“更新音频列表”动作，用户触发后经过草稿保存屏障更新当前媒体目录；不得因后台轮询重建当前 document、打断播放/草稿。已有媒体上的正常标注继续同步；含尚未加载媒体的作者层保留完整待应用数据/最后已验证层，并在状态中准确显示“有新增音频，更新列表后查看”，不能显示已完整同步或把未知媒体当作删除。更新列表完成后能看到全部新媒体和标注。该显式更新入口是本轮确定的边界，不承诺播放中自动插入新音频。

公共媒体不做物理删除，避免破坏他人的标注。原“移除音频”在新版项目变为“从我的列表隐藏”，仅改变本机显示偏好；提供“显示隐藏音频”恢复入口，不删除自己/别人标注、音频或历史。导出范围不受隐藏筛选影响。

## 4. 创建、打开、另存与分享

“新建项目”选择空目录直接建立新版协作项目并使用本机作者，可立即导入音频。项目入口继续使用 collaboration.json，UI 统一称“项目”；文件选择器识别项目入口，不需要用户理解后端类型。新项目菜单不显示“创建协作副本”。将整个项目文件夹放到 NAS 后其他用户可直接打开，新电脑默认自己的作者，看到既有作者图层，不需要转换或重新归属。

保留旧普通项目打开能力；旧项目可显式复制到新版项目，保持源不变，这属于打开旧文件的例外入口，不是新建默认流程。用户明确不需要历史数据迁移，所以不实现自动迁移或格式兼容写入。

“另存我的项目副本”保留已有“当前作者内容”的范围语义，创建新的默认项目、复制音频和当前作者标注，并保留本机个人设置到新项目的本机工作区；不认领其他作者内容。目标为空且不能在当前项目内部，失败保留原项目。无需把该动作扩展成全员分支/备份。导入现有 JSON/ZIP 分享文件也建立默认项目，并以当前本机作者拥有导入标注。导出我的标注/项目包继续排除屏蔽、音量、凭据和他人图层，完整音频包无需收件人另找源音频。整个 NAS 目录是全员共享载体。共享显示筛选/隐藏音频不改变导出数据。

## 5. 不变的正确性边界

每作者独立不可变快照和 OS 写锁；只有自己的图层可改。自己的重叠框和别人重叠框独立。音量、临时屏蔽、STFT/Mel/缩放、播放设备只存本机。A 发布在途、B 保存、C 未保存的确认逻辑仍保留较新状态；任何目录更新也不能重置这一保证。离线待同步、本机保存错误、权限错误、恢复和旧 runtime 拒绝继续可见且可恢复。身份切换使用原生命周期屏障，清理旧选区/播放意图。无改动轮询不触发频谱重绘/分析或播放重新配置。

## 6. Compatibility / Migration

- Backward compatibility: partial。
- Protected surfaces: 既有频谱/音频/标注交互、按作者隔离与个人设置不共享；旧普通文件和旧协作项目可显式打开，既有交换文件可导入；旧发布产物和用户配置目录原样保留。
- Allowed breakage: 新建/导入/另存的默认输出为新版项目，旧程序拒绝新版格式；新版默认退出返回本机作者；媒体移除是个人隐藏；协作副本菜单只用于旧项目。
- Migration strategy: none。无数据库/历史标注迁移，旧项目保持原样。内部旧普通文档可用于交换和测试，不等同于新项目的用户流程。

## 7. 验证与交付

先验证核心身份稳定性、加密/不泄露、并发创建、同账号锁、目录追加原子性和越界拒绝，再接 native 生命周期与 UI。测试两独立本机身份在同一项目创建重复框且互不覆盖；单人新建→文件夹导入→保存→关闭重开身份及框不变；另一目录/电脑身份不继承屏蔽/音量；另一作者新增媒体→紧凑提示→保存草稿后更新列表；隐藏/恢复不改公共内容；另存和分享导入都是默认项目。故障覆盖离线、只读、损坏本机身份、取消/旧 runtime、目录变化时的 pending/恢复。

执行完整前端、TypeScript、Rust workspace tests、fmt、clippy 和针对本轮流程的真实桌面双实例验收；既有单人/多通道/选择回归适配新默认路径，不能把所有测试都继续走旧项目。构建正常 Windows EXE/NSIS 0.4.0，更新简洁中文指南并冻结新目录 releases/0.4.0，不覆盖 0.3.0。沿用现有许可流程；无关依赖不升级，仅启用 windows-sys 必需 DPAPI 特性。物理 NAS 不具备时明确说明实测为同目录多进程。
